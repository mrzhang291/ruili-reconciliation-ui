# 锐力对账系统 · 飞书多维表格改造架构详解

> 版本：v1.0
> 日期：2026-08-18
> 状态：待评审
> 备注：本方案参考《钉钉多维表格改造架构详解》，将存储层从钉钉替换为飞书多维表格（Lark Base）

---

## 1. 背景与目标

### 1.1 现状问题

| 问题 | 说明 |
|------|------|
| SSH 兼容性问题 | 通过 SSH 隧道连接客户远程 PostgreSQL，各版本 OpenSSH 行为不一致，部署到客户电脑时排查耗时 |
| 依赖远程服务器 | 需要维护一台 PostgreSQL 服务器，客户运维成本高 |
| 团队不可见 | 对账数据存在本地数据库，客户团队无法直接查看 |

### 1.2 改造目标

| 目标 | 说明 |
|------|------|
| 去掉 SSH | 不再依赖 SSH 隧道，解决版本兼容问题 |
| 去掉远程服务器 | 不依赖自建 PostgreSQL，零运维 |
| 飞书多维表格作为数据库 | 飞书 Base 作为纯存储层，前端展示最终结果 |
| 原始文件存飞书 | 原始单据附件存入飞书 Base，前端展示时读取 |
| 统计分析能力 | 利用飞书 Base 原生聚合/公式/lookup 能力，后端代码更简单 |

## 2. 目标架构

```
┌─────────────────────────────────────────────────────┐
│  客户电脑                                     │
│                                                     │
│  ① 用户上传结算单 + ERP 文件                          │
│     ↓                                                │
│  ② 存本地临时目录（.runtime/tasks/<任务ID>/）           │
│     ↓                                                │
│  ③ Agent 对账                                        │
│     · 读本地文件 → 用 MinerU 识别 → 算 difference      │
│     · 中间状态存内存 Map（重启即丢，可接受）             │
│     ↓                                                │
│  ④ 任务完成 → 一次性写入飞书 Base（省 API 额度）        │
│     a. 创建任务记录（含结果）                          │
│     b. 上传两份原始文件到附件字段                       │
│     c. 写入差异明细（如有多条）                        │
│     ↓                                                │
│  ⑤ 后端读取飞书数据，前端展示最终结果                   │
│     · 任务列表 / 详情 / 审核明细 / 统计                │
│     · 团队在系统内查看，不去飞书                        │
└─────────────────────────────────────────────────────┘
```

### 2.1 组件清单

| 组件 | 技术 | 职责 |
|------|------|------|
| 前端 | React + Vite | 上传文件、轮询进度、展示对账结果 |
| 后端 | Express | 处理上传、编排对账、读写飞书 Base |
| Agent | CherryStudio 锐力 Agent | 识别文件、计算差异、返回 JSON |
| lark-cli / lark-base | 飞书官方工具链 | 操作飞书多维表格（MCP 层） |
| 飞书多维表格 | 飞书 SaaS | 纯数据库存储，前端读取展示 |
| 内存 Map | Node.js | 对账中间状态缓存（可丢失） |

## 3. 数据模型设计

### 3.1 飞书多维表格：表结构

#### 表 1：对账任务表

| 字段名 | 类型 | 说明 |
|--------|------|------|
| 任务ID | 文本 | 主键，UUID |
| 商城名称 | 文本 | 客户名称 |
| 账期 | 文本 | YYYY-MM |
| ERP金额 | 数字/货币 | 元 |
| 结算金额 | 数字/货币 | 元 |
| 差额 | 公式 | ERP金额 - 结算金额（自动计算） |
| 状态 | 单选 | 待处理 / 处理中 / 已一致 / 待审核 / 已审核 / 失败 |
| 结算文件 | 附件 | 原始结算单 |
| ERP文件 | 附件 | 原始 ERP 单据 |
| 完成时间 | 日期 | 时间戳 |
| 备注 | 文本 | 失败原因等 |

#### 表 2：审核明细表

| 字段名 | 类型 | 说明 |
|--------|------|------|
| 明细ID | 文本 | UUID |
| 任务ID | 文本 | 关联主表 |
| 商城名称 | 查找引用 | 通过任务ID关联主表自动带出 |
| 差异金额 | 数字/货币 | 元 |
| 差异描述 | 文本 | Agent 分析的差异原因 |
| 处理状态 | 单选 | 待处理 / 已通过 / 已忽略 |
| 建议 | 文本 | Agent 给的建议 |
| 创建时间 | 日期 | 时间戳 |

### 3.2 数据流转

```
PostgreSQL（删除）                 飞书多维表格（新增）
─────────────────                 ────────────────────
ReconciliationTask     ──────→    对账任务表
ReconciliationReviewItem ─────→  审核明细表
File                    ─────→   附件字段（存于任务记录）
```

### 3.3 中间状态（内存 Map）

不写入飞书，仅在后端内存中维护：

```ts
type TaskState = {
  taskId: string;
  status: 'QUEUED' | 'PROCESSING' | 'SUCCEEDED' | 'NEEDS_REVIEW' | 'FAILED';
  progressLogs: ProgressLog[];
  result?: CherryParseResult;
};
```

**注**：服务重启后内存状态丢失，未完成任务需重新上传（已确认可接受）。

## 4. 飞书 Base API 能力评估

### 4.1 支持的能力（对比钉钉大幅增强）

| 能力 | 支持情况 | 用途 |
|------|---------|------|
| 批量创建记录 | ✅ 单次最多 1000 条 | 任务 + 明细批量写入 |
| 查询记录 | ✅ `record-search` 服务端筛选 | 前端查询任务 |
| 排序 | ✅ API 支持多字段 ASC/DESC | 列表按时间/金额排序 |
| 聚合统计 | ✅ `data-query`（sum/avg/count/groupBy） | 统计页直接算 |
| 更新记录 | ✅ 批量更新 | 审批状态更新 |
| 删除记录 | ✅ 批量删除 | 任务删除 |
| 附件上传 | ✅ 附件字段 | 原始文件 |
| 公式字段 | ✅ 100+ 函数 | 差额自动计算 |
| Lookup 关联 | ✅ 跨表引用+聚合 | 明细表带出商城名称 |

### 4.2 与钉钉对比的优势

| 痛点（钉钉） | 飞书方案 |
|-------------|---------|
| API 不支持排序 | ✅ 飞书支持多字段排序 |
| API 不支持聚合/groupBy | ✅ `data-query` 原生聚合 |
| 公式字段 API 不开放 | ✅ 公式字段完全开放 |
| Lookup 字段 API 不开放 | ✅ 查找引用完全开放 |
| 标准版 5000 次/月 | ✅ 免费版 1M/月，商业版/企业版无限 |
| 分页 100 条/页 | ✅ 500 条/页 |

### 4.3 额度控制

| 项目 | 数值 | 说明 |
|------|------|------|
| 免费版月额度 | 约 1,000,000 次/月 | 2026-06 限时活动，常规 1-5 万 |
| 商业版/企业版 | 无调用次数限制 | 客户如有付费版则无忧 |
| 单任务调用 | 约 10-20 次 | 含任务创建、附件、明细、状态 |
| 预估月消耗 | 2000 次（100 任务） | 远低于免费额度 |

**省额度策略**：中间状态不写飞书，仅在任务完成时一次性写入。

## 5. 对账流程（改造后）

```
用户上传
   │
   ▼
POST /api/tasks
   │ ① 校验文件类型
   │ ② 保存到本地临时目录
   │ ③ 创建内存任务记录（QUEUED → PROCESSING）
   ▼
后端调用 CherryStudio Agent
   │ ① 找到"锐力" Agent
   │ ② 创建 Session
   │ ③ 发送提示词（含文件 URL + 对账口径）
   ▼
Agent 处理
   │ ① 下载/读取文件
   │ ② 用 MinerU 识别（PDF/图片）
   │ ③ 计算 difference
   │ ④ 调用 lark-base：写任务 + 附件 + 明细（存入数据库）
   ▼
Agent 返回 JSON 结果
   │ { matched, difference, issues, period, name }
   ▼
后端校验
   │ ① 校验 JSON 格式
   │ ② 校验数据类型
   │ ③ 更新内存状态（SUCCEEDED / NEEDS_REVIEW / FAILED）
   ▼
后端从飞书读取数据
   │ 前端轮询 /api/tasks/:id
   │ 返回进度 + 结果（前端展示，团队不去飞书）
   ▼
完成
```

## 6. 后端代码改造点

### 6.1 删除

| 文件/模块 | 说明 |
|-----------|------|
| `server/prisma/` | 整个 Prisma 目录删除 |
| `server/src/lib/prisma.ts` | Prisma 客户端删除 |
| SSH 隧道代码 | `start-all.mjs` 中 `ensureTunnel`、`sshEnvironment`、`ensureAskpassHelper` 等 |
| `server/.env` 中 SSH 配置 | `SSH_HOST`、`SSH_PORT`、`SSH_USER` 等 |
| `resumeIncompleteTasks()` | 重启恢复未完成任务（已确认不需要） |
| `pg_advisory_xact_lock` | PostgreSQL 行锁逻辑 |

### 6.2 新增

| 文件/模块 | 说明 |
|-----------|------|
| `server/src/lib/lark-base.ts` | 飞书 Base API 封装（token、附件、批量写入、聚合查询） |
| `server/src/lib/task-store.ts` | 内存 Map 状态存储 |
| lark-base 指令 | 写入 Agent 提示词 |

### 6.3 修改

| 文件 | 改动 |
|------|------|
| `cherrystudio.ts` | 提示词追加"对账完成后用 lark-base 写飞书"指令 |
| `reconciliation.ts` | 去掉 Prisma 事务，改为内存状态 + 完成后写飞书 |
| `tasks.ts` | 数据源从 Prisma 改为内存 Map + 飞书读取 |
| `review-items.ts` | 审批逻辑改为飞书 API（去掉事务锁） |
| `statistics.ts` | 统计用 `data-query` 聚合，或拉全量内存计算 |
| `file-storage.ts` | 文件改为本地临时目录，完成后上传飞书附件 |

## 8. 部署（交付给客户）

### 8.1 客户环境要求

| 项 | 要求 |
|----|------|
| 操作系统 | Windows 或 macOS |
| Node.js | ≥ 22.13 |
| CherryStudio | 企业版已启动，API 服务监听 `127.0.0.1:24333` |
| 飞书 | 已创建多维表格 + 企业内部应用凭证 |
| lark-cli | 已安装并授权（`lark-cli auth login`） |
| 网络 | 能访问飞书 API |

### 8.2 一键启动流程（改造后）

```
① 校验 Node.js 版本
② 安装依赖（npm ci）
③ 启动后端 + 前端
④ 前端连接设置：填 CherryStudio API Key + 飞书 AppID/AppSecret
⑤ 打开浏览器
```

**注意**：不再需要 SSH 密码、数据库密码、远程服务器。部署难度大幅降低。

## 9. 风险与注意事项

| 风险 | 影响 | 缓解 |
|------|------|------|
| 飞书 API 月额度 | 超量后服务不可用 | 免费版约 1M/月，企业版无限；监控调用量 |
| 附件上传失败 | 前端无法展示原始单据 | 附件失败不阻塞结果写入，单独重试 |
| 飞书 API 限频（50 QPS） | 批量写入被限流 | 批量接口控制在 1000 条内；失败指数退避重试 |
| Agent 写错数据 | 飞书表数据错误 | 后端校验 + 必要时手动纠正 |
| 中间状态丢失（重启） | 进行中任务需重传 | 已确认可接受 |
| 含公式/关联字段的表排序受限 | 排序/筛选受限 | 用 `data-query` 或预计算到普通字段 |
