# 锐力对账系统 · 钉钉多维表格改造架构详解

> 版本：v1.0
> 日期：2026-08-18
> 状态：待评审

---

## 1. 背景与目标

### 1.1 现状问题

| 问题 | 说明 |
|------|------|
| SSH 兼容性问题 | 通过 SSH 隧道连接客户远程 PostgreSQL，各版本 OpenSSH 行为不一致，部署到客户电脑时排查耗时 |
| 依赖远程服务器 | 需要维护一台 PostgreSQL 服务器，客户运维成本高 |
| 团队不可见 | 对账数据存在本地数据库，客户团队无法直接查看 |

### 1.2 改造目标

| 目标 | 说明 |
|------|------|
| 去掉 SSH | 不再依赖 SSH 隧道，解决版本兼容问题 |
| 去掉远程服务器 | 不依赖自建 PostgreSQL，零运维 |
| 钉钉多维表格作为数据库 | 钉钉作为纯存储层，前端展示最终结果 |
| 原始文件存钉钉 | 原始单据附件存入钉钉，前端展示时读取 |

## 2. 目标架构

```
┌─────────────────────────────────────────────────────┐
│  客户电脑                                     │
│                                                     │
│  ① 用户上传结算单 + ERP 文件                          │
│     ↓                                                │
│  ② 存本地临时目录（.runtime/tasks/<任务ID>/）           │
│     ↓                                                │
│  ③ Agent 对账                                        │
│     · 读本地文件 → 用 MinerU 识别 → 算 difference      │
│     · 中间状态存内存 Map（重启即丢，可接受）             │
│     ↓                                                │
│  ④ 任务完成 → 一次性写入钉钉数据库（省 API 额度）        │
│     a. 创建任务记录（含结果）                          │
│     b. 上传两份原始文件到附件字段                       │
│     c. 写入差异明细（如有多条）                        │
│     ↓                                                │
│  ⑤ 后端读取钉钉数据，前端展示最终结果                   │
│     · 任务列表 / 详情 / 审核明细 / 统计                │
│     · 团队在系统内查看，不去钉钉                       │
└─────────────────────────────────────────────────────┘
```

### 2.1 组件清单

| 组件 | 技术 | 职责 |
|------|------|------|
| 前端 | React + Vite | 上传文件、展示任务、轮询进度 |
| 后端 | Express | 处理上传、编排对账、调用钉钉 API |
| Agent | CherryStudio 锐力 Agent | 识别文件、计算差异、返回 JSON |
| 钉钉 MCP | `dingtalk-mcp` | Agent 操作钉钉多维表格的工具层 |
| 钉钉多维表格 | 钉钉 SaaS | 纯数据库存储，前端读取展示 |
| 内存 Map | Node.js | 对账中间状态缓存（可丢失） |

## 3. 数据模型设计

### 3.1 钉钉多维表格：表结构

#### 表 1：对账任务表

| 字段名 | 类型 | 说明 |
|--------|------|------|
| 任务ID | 文本 | 主键，UUID |
| 商城名称 | 文本 | 客户名称 |
| 账期 | 文本 | YYYY-MM |
| ERP金额 | 货币 | 元 |
| 结算金额 | 货币 | 元 |
| 差额 | 货币 | 元（可正可负） |
| 状态 | 单选 | 待处理 / 处理中 / 已一致 / 待审核 / 已审核 / 失败 |
| 结算文件 | 附件 | 原始结算单 |
| ERP文件 | 附件 | 原始 ERP 单据 |
| 完成时间 | 日期 | 时间戳 |
| 备注 | 文本 | 失败原因等 |

#### 表 2：审核明细表

| 字段名 | 类型 | 说明 |
|--------|------|------|
| 明细ID | 文本 | UUID |
| 任务ID | 文本 | 关联主表 |
| 商城名称 | 文本 | 冗余，方便直接看 |
| 差异金额 | 货币 | 元 |
| 差异描述 | 文本 | Agent 分析的差异原因 |
| 处理状态 | 单选 | 待处理 / 已通过 / 已忽略 |
| 建议 | 文本 | Agent 给的建议 |
| 创建时间 | 日期 | 时间戳 |

### 3.2 数据流转

```
PostgreSQL（删除）                 钉钉多维表格（新增）
─────────────────                 ────────────────────
ReconciliationTask     ──────→    对账任务表
ReconciliationReviewItem ─────→  审核明细表
File                    ─────→   附件字段（存于任务记录）
```

### 3.3 中间状态（内存 Map）

不写入钉钉，仅在后端内存中维护：

```ts
type TaskState = {
  taskId: string;
  status: 'QUEUED' | 'PROCESSING' | 'SUCCEEDED' | 'NEEDS_REVIEW' | 'FAILED';
  progressLogs: ProgressLog[];
  result?: CherryParseResult;
};
```

**注**：服务重启后内存状态丢失，未完成任务需重新上传（已确认可接受）。

## 4. 钉钉 API 能力评估

### 4.1 支持的能力

| 能力 | 支持情况 | 用途 |
|------|---------|------|
| 批量创建记录 | ✅ `insertNotableRecords` | 任务 + 明细批量写入 |
| 查询记录 | ✅ `listNotableRecords` + filter | 前端查询任务 |
| 更新记录 | ✅ `updateNotableRecords` | 审批状态更新 |
| 删除记录 | ✅ `deleteNotableRecords` | 任务删除 |
| 附件上传 | ✅ `attachment` 字段 | 原始文件 |
| 筛选 | ✅ 10 种运算符 | 按状态/账期筛选 |

### 4.2 不支持的（需规避）

| 能力 | 不支持 | 规避方案 |
|------|--------|---------|
| 事务 | ❌ | 批量接口保证一次写入；写失败重试 |
| 聚合/groupBy | ❌ | 拉取全量数据到内存计算（数据量小） |
| 排序 | ❌ API 不支持 | 内存排序 |
| 模糊搜索 | ⚠️ 仅 `contain` | 数据量小，拉取后过滤 |
| Decimal 精度 | ❌ 仅 number | 金额用货币字段，写入传字符串保证精度 |

### 4.3 额度控制

| 项目 | 数值 | 说明 |
|------|------|------|
| 标准版免费调用 | 5000 次/月 | 2025-09-01 起计费 |
| 单任务调用 | 约 10-20 次 | 含任务创建、附件、明细、状态 |
| 预估月消耗 | 2000 次（100 任务） | 在免费额度内 |

**省额度策略**：中间状态不写钉钉，仅在任务完成时一次性写入。

## 5. 对账流程（改造后）

```
用户上传
   │
   ▼
POST /api/tasks
   │ ① 校验文件类型
   │ ② 保存到本地临时目录
   │ ③ 创建内存任务记录（QUEUED → PROCESSING）
   ▼
后端调用 CherryStudio Agent
   │ ① 找到"锐力" Agent
   │ ② 创建 Session
   │ ③ 发送提示词（含文件 URL + 对账口径）
   ▼
Agent 处理
   │ ① 下载/读取文件
   │ ② 用 MinerU 识别（PDF/图片）
   │ ③ 计算 difference
   │ ④ 调用钉钉 MCP：写任务 + 附件 + 明细（存入数据库）
   ▼
Agent 返回 JSON 结果
   │ { matched, difference, issues, period, name }
   ▼
后端校验
   │ ① 校验 JSON 格式
   │ ② 校验数据类型
   │ ③ 更新内存状态（SUCCEEDED / NEEDS_REVIEW / FAILED）
   ▼
后端从钉钉读取数据
   │ 前端轮询 /api/tasks/:id
   │ 返回进度 + 结果（前端展示，团队不去钉钉）
   ▼
完成
```

## 6. 后端代码改造点

### 6.1 删除

| 文件/模块 | 说明 |
|-----------|------|
| `server/prisma/` | 整个 Prisma 目录删除 |
| `server/src/lib/prisma.ts` | Prisma 客户端删除 |
| SSH 隧道代码 | `start-all.mjs` 中 `ensureTunnel`、`sshEnvironment`、`ensureAskpassHelper` 等 |
| `server/.env` 中 SSH 配置 | `SSH_HOST`、`SSH_PORT`、`SSH_USER` 等 |
| `resumeIncompleteTasks()` | 重启恢复未完成任务（已确认不需要） |
| `pg_advisory_xact_lock` | PostgreSQL 行锁逻辑 |

### 6.2 新增

| 文件/模块 | 说明 |
|-----------|------|
| `server/src/lib/dingtalk.ts` | 钉钉 API 封装（token、附件、批量写入） |
| `server/src/lib/task-store.ts` | 内存 Map 状态存储 |
| 钉钉 MCP 指令 | 写入 Agent 提示词 |

### 6.3 修改

| 文件 | 改动 |
|------|------|
| `cherrystudio.ts` | 提示词追加"对账完成后用 MCP 写钉钉"指令 |
| `reconciliation.ts` | 去掉 Prisma 事务，改为内存状态 + 完成后写钉钉 |
| `tasks.ts` | 数据源从 Prisma 改为内存 Map |
| `review-items.ts` | 审批逻辑改为钉钉 API（去掉事务锁） |
| `statistics.ts` | 统计改为拉全量内存计算 |
| `file-storage.ts` | 文件改为本地临时目录，完成后上传钉钉附件 |

## 8. 部署（交付给客户）

### 8.1 客户环境要求

| 项 | 要求 |
|----|------|
| 操作系统 | Windows 或 macOS |
| Node.js | ≥ 22.13 |
| CherryStudio | 企业版已启动，API 服务监听 `127.0.0.1:24333` |
| 钉钉 | 已创建多维表格 + 企业内部应用（AppKey/AppSecret） |
| 网络 | 能访问钉钉 API（https://api.dingtalk.com） |

### 8.2 一键启动流程（改造后）

```
① 校验 Node.js 版本
② 安装依赖（npm ci）
③ 启动后端 + 前端
④ 前端连接设置：填 CherryStudio API Key + 钉钉 AppKey/AppSecret
⑤ 打开浏览器
```

**注意**：不再需要 SSH 密码、数据库密码、远程服务器。部署难度大幅降低。

## 9. 风险与注意事项

| 风险 | 影响 | 缓解 |
|------|------|------|
| 钉钉 API 月额度 5000 次 | 超量后服务不可用 | 完成任务时批量写入；监控调用量 |
| 附件上传失败 | 前端无法展示原始单据 | 附件失败不阻塞结果写入，单独重试 |
| 钉钉 API 限频（20 QPS） | 批量写入被限流 | 批量接口控制在 100 条内；失败指数退避重试 |
| Agent 写错数据 | 钉钉表数据错误 | 后端校验 + 必要时手动纠正 |
| 中间状态丢失（重启） | 进行中任务需重传 | 已确认可接受 |
